# 摄像头实时识别 Demo —— 讲解文档

> 配套脚本：`camera.py` | 需要：电脑摄像头

## 1. 摄像头实时识别和图片识别的区别？

**本质完全一样**，只是输入变成了"连续的画面流"：

```
图片识别:  一张图 ──► 模型 ──► 类别
摄像头:    帧1→帧2→帧3→...→帧30（每秒） ──► 每帧都识别一次
```

摄像头本质就是一台**每秒拍 30 张图**的相机。所以实时识别 = 不断"拍图 + 推理 + 显示"的循环。**实时性的瓶颈是推理速度**——模型快，画面就流畅。

## 2. 脚本结构（一个死循环）

```python
while True:
    frame = cap.read()                    # 1. 取一帧画面
    results = model.predict(frame, ...)   # 2. 推理这一帧
    # 3. 解析结果、画文字
    cv2.imshow("ASL Recognition", frame)  # 4. 显示
    if cv2.waitKey(1) & 0xFF == ord("q"): # 5. 检测按键退出
        break
```

这个"取帧→推理→显示→等按键"的循环，是几乎所有实时视觉应用（人脸识别、车牌识别、AR）的通用骨架。

## 3. 关键函数逐个拆解

### `cv2.VideoCapture(0)`
打开摄像头设备。参数 `0` = 系统第 0 号摄像头（通常是内置/默认）。如果笔记本外接摄像头，可能是 `1`、`2`。

### `cap.read()`
取当前时刻的一帧画面。返回两个值：
- `success`：这一帧取到没有（摄像头被占用、拔掉时会失败）
- `frame`：画面本身，一个三维数组 `[高, 宽, 3]`（BGR 三通道）

### `cv2.putText(...)`
在图像上写字，参数依次是：图片、文字、坐标、字体、字号、颜色、粗细。用于把识别结果"贴"在画面上。

### `cv2.waitKey(1)`
让窗口响应键盘输入，等待 1 毫秒。返回按下的按键。`ord("q")` 是字符 `q` 的 ASCII 码，按下就退出循环。

## 4. 置信度阈值在这里的用处

实时场景里，手会不断移动、虚焦、遮挡，模型常常"拿不准"：

```
手举好（清晰）  →  A 98%   → 显示 "A"
手晃了一下     →  A 45%   → 低于阈值，显示 "?  45%"
```

`--conf 0.5` 的意思是：**置信度低于 50% 时不要自信地报字母**，显示"不确定"，避免误报。这是所有识别系统都要做的**防误报**处理。

## 5. 运行方法

```bash
python camera.py                          # 默认摄像头
python camera.py --cam 1                  # 外接摄像头
python camera.py --conf 0.7               # 更严格，减少误报
```

启动后对准摄像头做手势字母（A/B/C...），窗口左上角实时显示识别结果，按 `q` 退出。

## 6. 学习要点

1. **"实时" = 循环 + 够快的单帧推理**。我们的模型单帧 6ms，非常快，所以流畅。
2. **每一帧都是独立判断**：模型没有"记忆"，前一帧识别 A 不影响这一帧。这也是为什么下一步（T10）要做"累积"——把一帧帧的结果拼成有意义的文字。
3. **摄像头画面 ≠ 训练集图片**：训练图是干净的 200x200 特写，摄像头画面有背景、距离、光线差异，所以实时准确率通常比测试集低——**这很正常**，全量训练能改善。

## 7. 下一步预告

`camera.py` 只能"显示当前字母"。T10 会加上**累积逻辑**：识别到字母就拼进一个字符串（像打字一样），自动处理"同一字母重复帧"，最终输出一段拼音/文字。
