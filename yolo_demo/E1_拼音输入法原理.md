# E1 原理笔记：输入法如何从字母推算出句子

> 任务目标：搞懂拼音输入法/T9 智能输入"字母串 → 拼音 → 汉字句子"的完整原理，
> 为手语打字机（字母串）接上"拼音理解与补全"打基础。

---

## 1. 一句话总结

输入法推测句子 = **把一串连续拼音，通过"切分 + 映射 + 打分"找到概率最大的那句话**。

```
用户敲下: nihao
模型思考: 怎么切成拼音?  ni|hao  (还是 n|i|h|ao? nianhao?)
          每段拼音对应哪些字?   ni→{你,泥,尼}  hao→{好,号,豪}
          哪几个字组合成句概率最高?  你+好 (远高于 泥+号)
输出:     候选 [你好] [您好] ...
```

核心是 4 个组件，环环相扣。

---

## 2. 四个核心组件

### ① 拼音→汉字 映射表（同音字/词表）
把每个拼音音节映射到它可能的汉字：

```
ni   → 你(0.9) 泥(0.04) 尼(0.02) 拟(0.02) ...
hao  → 好(0.8) 号(0.1) 豪(0.05) 耗(0.03) ...
```
每个字带一个**字频**（这个字在语料里出现多频繁）。表越大、越准，候选越全。

### ② 语言模型（n-gram）：给"字与字的搭配"打分
单靠字频不够——`你+号` 两个高频字但组不成常用词。语言模型统计**词串共现概率**：

```
P(你好) >> P(泥号) >> P(你号)
```

- **一元模型 (unigram)**：P(好) = 好单独出现的概率
- **二元模型 (bigram)**：P(好|你) = "你"后面跟着"好"的概率
- **三元模型 (trigram)**：P(好|你在) = "你在"后面跟"好"的概率

句子概率 ≈ 各词间条件概率连乘：
```
P(你好) ≈ P(你) × P(好|你)
```

**训练来源**：海量中文语料统计（新闻、小说、聊天），这就是输入法"越用越聪明"的原因——它统计的是真实语言习惯。

### ③ 整句解码（动态规划 / Viterbi）
输入 `nihao` 时切分和选字有海量组合：

```
ni|hao              → 你好 / 您好
n|i|h|a|o           → (单字母拼音，大多不成字)
ni|ha|o             → ...
nian|hao?  ...
```

Viterbi 算法做的是：**在所有这些路径里，找到整句概率乘积最大的那一条**。它把问题拆成子问题一步步推进（动态规划），复杂度可控，不是暴力枚举。

### ④ 候选排序与联想
- 算出 Top-N 条完整句子，按概率从高到低显示在候选栏
- 用户选 1（默认最高分），不满意按 2/3/4... 选别的
- 更智能的会结合**上下文**：上一句是"今天天气真"，下一句自动把"好"提到候选第一

## 3. 一张数据流图

```
用户按键字母流 n-i-h-a-o
        ↓
① 拼音切分器: 切成拼音音节候选  ni|hao, nian|hao, n|i|h|a|o...
        ↓
② 拼音→汉字表: 每段展开成多候选字/词  ni→{你,泥,...}
        ↓
③ 语言模型: 为每种"切分+选字"组合计算整句概率
        ↓
④ Viterbi 解码: 挑概率最高的路径 → 得到"最可能的句子"
        ↓
输出候选列表: [你好] [您好] [泥嚎]...
```

## 4. 和我们手语场景的类比

| 输入法 | 手语打字机（我们的场景） |
|--------|------------------------|
| 键盘敲字母流 nihao | 摄像头识别出的字母流 HELLO / NIHAO |
| 拼音切分 ni\|hao | 字母串→音节切分（手语无空格更难） |
| 拼音→字表 | 拼音→中文词映射 |
| n-gram 语言模型 | 同样的语言模型 |
| Viterbi 整句解码 | 同 |

**差异点**：
- 输入法字母是"准确输入"，手语是"概率输入"（每帧带置信度、可能识别错）→ 需要**纠错容忍**
- 手语无空格/边界 → 切分更难，更需要语言模型兜底

---

## 5. 关键技术名词速记

| 名词 | 一句话含义 |
|------|-----------|
| **n-gram** | 用前 n-1 个字预测第 n 个字概率的统计模型 |
| **Viterbi 解码** | 动态规划求"概率最大的状态路径" |
| **动态规划 (DP)** | 拆子问题、存中间结果、避免重复计算 |
| **字频/词频** | 单字/词在语料中出现比例 |
| **Perplexity (困惑度)** | 语言模型好坏的衡量指标，越低越好 |
| **Beam Search** | 每次保留 Top-K 条路径继续探索（大模型解码常用，比纯 Viterbi 灵活） |

## 6. 落地时的选型建议（供 E2 设计参考）

1. **拼音→字表**：用开源词库（如 THUOCL、搜狗词库转出的拼音表）
2. **切分器**：先做"全切分"（枚举所有合法拼音切分）再用 Viterbi 选最优
3. **语言模型**：入门用 bigram/trigram（统计计数即可）；进阶可换 jieba/bert 等
4. **纠错**：给手语识别的置信度加权——低置信度字母允许被词典纠错
5. **简化路径**：若只做 Demo，可先只支持"整词匹配"（字母串恰好是某词的拼音 → 直接出该词候选），再逐步上 n-gram

---

## 7. 结论

输入法推算句子的本质是**统计语言模型 + 解码搜索**，不是玄学：
给你一串带噪声/无边界的字母流，用"拼音表 × 语言概率"在搜索空间里找最合理的句子。
这正是文章方案里 RAG「句意连续」和 Agent「歧义决策」在输出端的技术实现。
