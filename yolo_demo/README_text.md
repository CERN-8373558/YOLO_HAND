# 摄像头手语打字机（文字串累积）—— 讲解文档

> 配套脚本：`camera_text.py` | 前置：T9 摄像头识别

## 1. 解决的问题

T9 的 `camera.py` 只能"实时显示当前字母"，但手语交流需要**连成文字**。T10 把它升级成"打字机"：

```
做"H"手势 → 屏幕累积 H
做"E"手势 → HE
做"L"手势 → HEL
做"space"手势 → HEL      （加空格）
做"del"手势 → HEL      （退格删一个字符）
```

## 2. 三大核心机制

### 机制一：防抖确认（最关键）

手语动作有起止过程，手从一个字母移到下一个时，模型可能在 A/B/C 间**来回跳变**几帧。如果不处理，一次移动会打出一串乱码。

解决：**同一手势必须连续稳定 N 帧才算数**（`STABLE_FRAMES=8`）：

```
帧:  A A A B B A A A A A A A A
     不稳定跳变     从A连续8帧 → 输出 A
```

代码里的状态机（伪代码）：
```
手上没手 → 重置计数（这段手势结束）
字母变化 → 重置计数（新手势开始）
字母相同 → 计数+1；达到 STABLE_FRAMES → 输出一次
```

### 机制二：特殊手势映射成"控制键"

分类模型除了 26 个字母，还识别了 3 个特殊类，正好映射成键盘操作：

| 手势类别 | 含义 | 动作 |
|---------|------|------|
| 普通字母 (A~Z) | 字母 | 追加到文字串 |
| `space` | 空格 | 加一个空格 |
| `del` | 删除 | 退格删一个字符 |
| `nothing` | 无手势 | 忽略（什么也不做） |

这其实就是**"用眼睛打字"**——把视觉识别结果翻译成键盘输入事件。

### 机制三：TextBuffer 缓冲区

```python
class TextBuffer:
    def __init__(self): self.chars = []   # 存字符的列表
    def append(self, ch): self.chars.append(ch)   # 追加
    def backspace(self): self.chars.pop()          # 退格
    def clear(self): self.chars.clear()            # 清空
    def text(self): return "".join(self.chars)     # 拼成字符串
```

为什么用 `list` 而不是直接拼 `str`？
- Python 字符串**不可变**，每次 `+` 都要新建整个字符串，频繁操作浪费
- `list` 的 append/pop 都是 O(1)（常数时间），适合高频追加/删除

## 3. 状态机图

```
        抬新手势
  ┌───────────────────────┐
  │                       ▼
没有手 ──→ 识别中(current_cls) ──→ 同一字母连续8帧 ──→ 输出并继续累积
  │           │
  └───────────┘
   手放下(重置)   手势变化(重置计数)
```

## 4. 运行方法

```bash
python camera_text.py                     # 默认参数
python camera_text.py --stable 12         # 提高稳定帧数（更稳但更慢）
```

按键：
- `q`：退出
- `c`：清空已输入的文字

操作建议：
1. 先做一个字母（如 H），**保持 0.5 秒**让它确认输出
2. 放下手，再比下一个字母
3. 单词拼完比 `space` 手势
4. 打错比 `del` 手势删掉

## 5. 学习要点

1. **现实信号需要"去抖"**：物理世界的手势/声音/传感器都带噪声，连续确认 N 次是通用降噪手法（按键防抖同理）。
2. **分类结果可以翻译成"控制指令"**：模型不只输出"是什么"，还能驱动 del/space/清空等动作——这是"视觉→控制"的思路雏形。
3. **状态机让逻辑清晰**：把"没有手/识别中/确认"的状态画出来，代码就好写了，Bug 也少。
